# 액체 재질 기준 · 독립 렌더와 중단한 후보

2026-09-09. **실제 Liquid Wave 외관 목표는 미달. 앱 채택 없음.** 아이폰에 설치한 build 3과 수위 복구 수정은 유지한다. 이번 결과는 Mac의 연구 코드·별도 렌더이며 폰의 실시간 업데이트가 아니다.

## 이번에 구분한 것

- 실제 구면으로 기포를 조회하면 이전 정지 장면의 광학 오류 5개가 사라졌다. 얇은 맑은 벽막은 액체 안쪽의 긴 흰 접촉선을 줄였다. [앞선 근거](ParticleSurface.md).
- 성분별 반지름을 맞추는 Zhu–Bridson 후보는 움직임에서 지지 범위 안의 명목 체적을 만들지 못해 중단했다. 상한을 계속 늘리지 않는다.
- 고정 GPU 커널로 복귀한 48프레임은 모두 생성됐지만 **광학 FAIL**이다. 37프레임에서 총 93개의 오류 픽셀, 한 프레임 최대 12개. 출력은 1200×2544, 영상은 실제 48프레임·2초·24fps다. GPU 표시 계산은 3.83~4.83초/프레임이며 실시간 성능이 아니다. PNG 48개 해시 일치 PASS. `.build-cache/material-kernel-film/`.
- 사선 시점은 이 재질 분리를 해결하지 못했다. 큰 본체의 평면감과 밝은 외곽이 그대로 남고 바닥에 넓은 띠가 생겼다. 별도 카메라 변경은 채택하지 않는다.

## 바깥 용기 표면

`VesselShell.metal`, `prepare_vessel_shell.py`, `VesselShellChecks.swift`는 기존 두 매질 밖의 공기/투명 용기 경계를 추가하는 단위다. air 1.0, shell 1.49, 두께 .006은 처방 값이며 실물 측정값이 아니다. 기존 672바이트 uniform과 mode bit 1024를 사용한다.

초기 Terra 전달본은 진입 법선 반전, 경계 초과 뒤 처리, 반사 에너지 중복 등의 문제가 있어 GPU 실행 전에 root가 거절하고 경계 이동을 다시 작성했다. 현재 구현은 다음 구간을 바깥 벽과의 해석적 교차로 제한하고, 나간 투과 에너지만 조명에 더한 뒤 반사 잔량은 용기 안에서 계속 추적한다. 기존 액체 반사의 짧은 환경 조회 근사는 남아 있다.

- 꺼짐 대조: 원래 고정 커널 첫 PNG와 **바이트 동일 PASS**. 원래 있던 오류 1픽셀도 동일하므로 전체 광학 PASS라는 뜻은 아니다.
- 반사/투과 계수·방향·벽 안쪽 복귀 27개: 독립적인 반복 반사 에너지 합과 대조 **PASS**, 최대 차이 1.79e-6.
- 전체 경로: 큰/작은 화면 모두 GPU recovery 오류가 발생했다. 두 픽셀 프로브는 완료됐고 32×4 픽셀 단위로 나눈 300×636 렌더는 완료됐지만 **오류 2,106픽셀, GPU 43.09초, 미감 FAIL**이었다. 계수 검사 통과를 경로 성공으로 확대하지 않는다. 원인이 GPU 부하만이라고 단정하지 않는다.
- 하얀 반사 막과 재질 분리가 남아 미채택. 오류를 배경색으로 숨기거나 광선 한도를 늘려 통과시키지 않았다. `.build-cache/material-vessel-shell/`에 로그·PNG·검사 결과를 보존한다.

## 같은 형상을 Blender로 비교

이미 설치된 Blender 5.0.1의 Cycles CPU를 사용했다. 새 프로그램·의존성·배포 자산을 설치하지 않았다. 자체 광선 추적만 계속 고치는 대신 다른 렌더러에서도 같은 외관이 나오는지 확인하는 목적이다.

`ExportLiquidMesh.cpp`는 동결된 GPU 필드에서 cubic B-spline 격자 중심 값을 계산하고 기포를 자른 뒤 삼각형 표면을 만든다. 전체 입자 시뮬레이션을 다시 만들거나 실물 형상으로 바꾼 것은 아니다. 외부 한 층으로 벽 접촉부를 닫으며 원래 필드와의 세부 보간 차이가 있다.

- 원래 표면: 647,662 vertex / 1,295,308 face. 모든 mesh edge가 반대 방향으로 정확히 두 면에 속함, 유한 좌표·양의 signed volume **PASS**. 적분 체적 1.06772는 mesh 값이며 실제 액체의 질량이 아니다.
- `BlenderLiquidReference.py`: 같은 정면 시점·흡수 계수·방 조명 배치로 비교한다. 상대 IOR, 실제 경로의 색 흡수, 64-bounce 제한과 denoising을 명시한다. 범선·화면 테두리는 이 비교에서 제외했다. Cycles와 Metal의 픽셀 일치를 주장하지 않는다.
- 내부 경계만 렌더한 600×1272·64sample 기준은 약 16.9초. 자체 렌더와 거의 같은 평평한 본체/밝은 가장자리 인상이 남았다. **렌더러 교체만으로 해결되지 않았다는 관찰**이며 모든 광학 코드가 정확하다는 증명은 아니다.
- 바깥 맑은 매질을 더한 1200×2544·128sample 기준은 약 199.6초. 광택의 실마리는 생겼으나 전면 조명 카드가 넓은 흰 사각형으로 비쳐 **미감 FAIL**.
- 카드 위치를 화면 밖으로 옮긴 600 비교에서는 넓은 흰 막이 없어졌지만 큰 본체의 평면감은 남았다. 현재 앱의 색 `(0.025,0.18,0.72)` 대조도 이를 해결하지 못했다. 작은 비교의 개선을 정상 크기의 실물 미감 통과로 판단하지 않는다.

Blender의 [Glass BSDF](https://docs.blender.org/manual/en/5.2/render/shader_nodes/shader/glass.html)와 [5.0.1 kernel의 volume absorption 처리](https://github.com/blender/blender/blob/v5.0.1/intern/cycles/kernel/svm/closure.h#L1117)를 참고했다. 흡수 계수는 `(1−color)×density`에 맞춰 지정한다. 유한 bounce·노이즈·집광 한계는 [공식 Cycles 설명](https://docs.blender.org/manual/sl/5.0/render/cycles/render_settings/light_paths.html)에 따라 별도의 제한으로 남긴다. 실물 액체의 굴절률·흡수량을 측정한 것은 아니다.

### 좁은 둥근 단면의 비교

큰 성분의 투영 외곽을 기준으로 깊이 단면의 둥근 부분을 .025로 좁힌 별도 mesh도 만들었다. 분리된 방울은 원래 깊이를 유지했다. mesh의 닫힘/방향 검사는 PASS지만 체적은 1.14037로 바뀌었으며 질량 보존 모델이 아니다. 600 비교에서 액체가 납작한 색면처럼 보이고 외곽도 거칠어져 **미채택**했다. 이를 기본 표면으로 바꾸거나 체적을 맞추는 후속 조정으로 연장하지 않는다.

### 소스 추적의 한계와 보완

첫 `vessel-1200` 렌더 중 유지 소스가 잠시 다음 버전으로 바뀌어, 종료 시 읽은 manifest의 소스 해시가 실제 실행 버전과 달라졌다. 원래 manifest/log를 삭제하거나 몰래 수정하지 않았다. 실행 전 알려진 해시와 일치하는 v1 소스를 복원·보존하고 `vessel-1200-provenance-correction.json`에 불일치와 보완 근거를 기록했다. 이후 실행은 시작 시 소스 사본을 저장하고 그 사본의 해시를 사용한다. 해당 최초 manifest만으로 현재 유지 소스의 실행을 증명하지 않는다.

## 다음 구현의 경계

이번 계열은 미감 개선이 정체돼 체크포인트로 묶는다. 기본 GPU 커널의 형상에 색·굴절 계산을 추가하는 반복은 이어가지 않는다. 다음 단위는 **원본 장난감의 둥근 액체 단면과 조명 조건을 함께 만든 기준 장면**부터 시작해야 한다. 큰 본체→목→끝이 한 재질로 읽히는 정상 크기 결과를 얻기 전에 실시간 렌더러 최적화나 앱 통합을 확대하지 않는다. 기존의 회전·수위 복구·질량 관련 동작을 포기한다는 뜻은 아니다.

실물 미감, 시간축의 합침/분리, iPhone 성능은 각각 별도 기준이다. 설치된 앱과 물리/renderer/shader/core-test 네 파일의 해시는 이번 작업 전후 동일했다. 새 iPhone 빌드·설치는 **NOT_RUN**이며 현재 후보를 설치할 이유가 없어 케이블 연결을 요청하지 않았다.
