# 연결부 명암 연구 — 미채택

2026-09-09. 사용자가 최근 광학 후보에서 몽글한 부피감이 사라졌다고 판단해 그 방향을 제외했다. 기본 앱의 둥근 끝·두툼한 몸통·늘어나는 목·분리 방울을 보존하면서, 연결 뒤에도 각 공이 따로 읽히는 국소 명암만 줄일 수 있는지 확인했다.

`ConnectedShading.swift`는 검사 하니스가 읽은 원래 셰이더 문자열의 opticalPath 부분만 변환한다. 네 방향의 대향 표본 중 양쪽 액체가 지지하는 밀도 골을 보정한다. 추정 광학 두께이며 실제 액체 두께나 물성을 측정한 값이 아니다. 앱 타깃에는 포함하지 않았다.

## 두 후보의 결과

- 첫 후보는 meniscus도 약하게 했다. 그러나 meniscus가 표면 법선 계산에도 쓰여 입체 명암까지 바뀌었고, 비평가가 밝은 쐐기·평평해진 부분을 발견했다. 미채택이며 소스와 PNG를 `.build-cache/reviews/connected-shading/normal-altered/`에 보존했다.
- 둘째 후보는 그 부작용을 제거하고 opticalPath만 바꿨다. 최초 비평은 형태 유지·개선 미미·일부 목이 더 옅다고 보았지만, 기준 PNG 생성 시각이 오래됐고 현재 소스 대응이 검증되지 않았음을 구조 검토에서 발견했다. **최초 비교를 근거로 보정이 밝아지게 했다는 인과 해석은 철회한다.** 같은 계수의 추가 조정은 하지 않는다.
- 현재 코드로 기본과 둘째 후보 모두 다시 렌더했다. 소스 해시·옵션·실제 컴파일 셰이더를 함께 저장했다. 물리·렌더러·하니스 해시는 동일하고 셰이더 차이는 opticalPath 보정뿐이다. 5자세 픽셀 비교에서 후보가 2/255 넘게 밝아진 픽셀은 0, shake 변화 범위 -32~+1/255.
- 전담 비평가가 재생성된 세 쌍을 다시 읽었다. 몽글함은 유지되고 일부 목에서 청색이 조금 더 이어지지만, 별도 공처럼 읽히는 인상을 확실히 줄이지는 못했다. rest/tilt 인상은 거의 같았다. **시각적 이득 부족으로 채택 보류.** 큰 퇴행이 없다는 사실과 실물 목표를 달성했다는 판단은 다르다. 시간순 검증으로 확대하지 않는다.

## 실제 검사와 한계

- PASS: `SMALLWAVE_CONNECTED_SHADE=1 DEVELOPER_DIR=/Library/Developer/CommandLineTools sh scripts/test-render.sh`. 둘째 후보의 Mac Metal 컴파일·다섯 자세·양쪽 화면 회전. 회전 평균 채널 오차 0.00002752 / 0.00007469, 이상치 0%.
- PASS: 첫 후보와 동일 입력 기본의 일곱 coverage PNG가 바이트 단위로 일치했다. 둘째 후보는 coverage 변경 없이 meniscus 수정만 제거했다. 둘째 mask는 재실행하지 않았다.
- PASS: 앱 core/renderer/shader SHA256이 연구 전 기본과 동일. 비교 페이지의 로컬 참조 27개 존재, 옛 실험을 감춘 details 닫힘 확인.
- PASS: 최종 하니스에서 기본·후보를 재실행했다. 모든 렌더 성공 뒤 기록한 완료 시각, 각 7개 PNG 해시, 실제 컴파일 셰이더 해시를 파일과 대조했다. 중간 실패로 이전 이미지가 남았을 때도 완료 manifest와 대응하는지 확인할 수 있다. 환경 기록은 실제 사용하는 8개 연구 옵션으로 제한한다.
- NOT_RUN: 이번 후보의 시간순 비교·iPhone 빌드/설치/센서/성능, 비교 HTML의 브라우저 표시. 정지 PNG와 회전 일치로 전체 물성이나 미감을 합격시키지 않는다.

현재 후보 PNG: `.build-cache/previews/connected-shading/`. 동일 순간 기본 PNG: `.build-cache/previews/`. `References/liquid-wave/comparison/baseline-shake.png`는 다른 시간의 보관본이므로 정확한 A/B 비교에는 사용하지 않는다.

다음 결정은 계수 튜닝보다 원래 렌더에서 반복 명암이 생기는 경로의 분리다. 현재 후보를 앱의 개선 결과로 제시하지 않는다.
