# 두 액체가 공유하는 흐름 — 수치·8초 모션 검증, 앱 미채택

2026-09-09. 사용자 요청에 따라 작업을 계속한다. 최근 화면 공간의 색·명암·기포 조정은 실물 외관을 충분히 개선하지 못했다. 다음 가설은 파란 액체와 맑은 부분이 같은 공간에서 서로 영향을 주며 움직이도록 계산하는 것이다. 이 가설의 효과는 아직 확인하지 않았다.

## 이번 단위

기존 앱을 보존한 독립 2D 연구다. 셀에는 파란 액체의 비율 c, 면에는 속도를 두고 맑은 부분은 1−c로 정의한다. 압력을 함께 계산하고 양을 보존하는 방식으로 c를 옮긴다. 첫 단위는 압력 투영·이동 계산의 정확성과 작은 틈의 보존까지다. 표면장력·입체 광학·장난감 결합·앱 채택은 이 단위에 포함하지 않는다.

저차 이동 기준선과 범위를 제한한 FCT 이동을 비교한다. 낮은 차수와 높은 차수의 flux를 조합하는 방법의 1차 참고는 [Zalesak의 FCT 논문](https://data.coaps.fsu.edu/pub/eric_back/OCP5930/Papers/FCT-JCPv31.pdf)이다. MAC 격자의 압력 투영은 [Bridson의 강의 노트](https://www.cs.ubc.ca/~rbridson/fluidsimulation/fluids_notes.pdf)를 참고한다. 원문 방법의 완전한 재현이나 실물 물성의 검증으로 주장하지 않는다.

## 사전 검증 기준

- Double c의 범위 오차 1e−12 이하. 전체 파란 양의 변화/전체 영역 크기 1e−9 이하. 사후 clamp나 전체 양 재조정으로 통과시키지 않는다.
- 실제 발산과 압력 잔차를 모두 확인한다. dt×최대 발산 1e−6 이하가 공개 veto이며, c 범위를 지키기 위한 내부 압력 목표는 더 엄격하게 둔다. 벽을 통과하는 흐름은 0이어야 한다.
- 압력 계산과 별도로 주어진 비압축 가역 흐름에서 원형 pocket과 떨어진 두 영역을 이동·복귀시킨다. 양·범위·위치·계면 폭·연결 성분을 비교한다. 맑은 틈이 퍼져 사라지면 양이 맞더라도 형태 보존 성공으로 보지 않는다.
- 정지 성층과 밀도 대비 0에서 임의의 흐름이 생기지 않아야 한다. 이후 제한된 기울임·뒤집기로 이동 방향과 양·발산을 검사한다.

## 제품 판정과 구분

새 계산이 더 매끈하다고 두 액체의 공유 압력이 원인이라고 결론내리지 않는다. 이후 같은 격자·이동·입력에서 압력 처리만 다른 대조가 필요하다. 셀보다 작은 목이나 간극의 분리·병합은 해상도에 따른 사건이며 실물의 병합 검증이 아니다.

제품 렌더가 준비되면 정상 크기에서 세 관계를 먼저 본다. 둥근 끝과 목이 같은 액체인지, 청색 부피와 맑은 틈이 구별되는지, 표면의 밝음과 청색 내부가 한 재질로 이어지는지다. 현재 수치 검사용 자료를 개선된 앱 화면으로 보여주지 않는다.

## 첫 실행과 독립 검토

Astra 구현 담당의 첫 CPU 실행은 실패 0이었다. `.build-cache/previews/two-phase/run-2026-09-09T17-30-22Z-BC31FF/`에 원래 contract·checks·CSV·JSON을 보존했다. phase 양/범위와 압력 검사는 기존 기준을 통과했고, FCT가 donor보다 덜 퍼졌다. 하지만 Sol 독립 검토에서 한 셀 잔재도 연결 성분으로 셀 수 있고 전체 peak 하나만 보던 한계를 찾았다. 따라서 **resolved 형태 보존을 통과했다는 최초 표현은 아직 근거가 부족하다.** 맑은 틈이 제품에서 자연스럽다는 뜻으로 확대하지 않는다.

검사 보완은 Terra에게 맡겼다. 원래 양·범위·발산 veto를 유지하며, 각 성분의 core 면적·양·peak와 개별 복귀 위치, 계면 폭을 확인한다. 기준 보완의 목적은 대부분 퍼진 뒤 작은 잔재만 남은 상태를 거르는 것이다. 각 core는 초기 최솟값의 50% 이상 면적·양과 최소 16셀, peak 0.9 이상을 유지해야 한다. 개별 복귀 오차는 1.5셀 이하, 계면 폭은 초기 pocket 반지름 이하로 제한한다. 이는 최소 수치 잔존 조건이며 실물 형상 정확도나 미감의 합격 기준이 아니다. 새 기준은 다음 실행 전에 contract에 저장한다. donor의 형태 실패는 비교 관측으로 남기고 FCT의 실패는 채택 차단으로 처리한다.

함께 고칠 증거 결함은 이류만 실행할 때 JSON의 time이 0이던 점이다. 실제 fixture 시각과 simulation clock을 구분해 저장한다. `step` 실패 후 일부 속도 변경이 남는 API 제한은 현재 하니스의 즉시 종료에는 영향을 주지 않지만, 향후 같은 인스턴스로 adaptive retry할 때 그대로 사용하면 안 된다.
