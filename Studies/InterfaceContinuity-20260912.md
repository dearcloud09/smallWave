# 수면과 본체의 연결 — 진단, 재질 개선판 아님

사용자의 build 5 실기기 화면은 넓은 청록색 테두리와 파란 본체가 다른 재질처럼 읽힌다. 정상 크기의 실제 장난감 사진과 Gadgetify 영상 2:18 부근을 기준으로 비교했다. 이번 새 브라우저 관찰은 선택 시점이며 두 영상을 처음부터 끝까지 시청한 것은 아니다.

## 확인한 원인 범위

인터페이스의 반사 기여만 끈 대조에서도 안쪽의 넓은 청록~파랑 전이는 남았다. 따라서 표면 반사광 하나가 전체 색 띠의 원인이라는 가설은 지지되지 않았다. 반사 제거를 앱에 채택하지 않았다. 초기 reflection AOV 실행 중 다른 작업의 공용 셰이더 변경이 있었으므로 그 AOV의 전체 입력 동결을 주장하지 않는다.

후속으로 소스 9개를 `.build-cache/interface-20260912/frozen-runtime/`에 복사해 동결하고, 같은 상태의 정상 렌더와 파란 액체 통과 길이 표시를 새로 실행했다. 두 결과의 시뮬레이션 상태 해시와 raw 경로 진단 버퍼가 동일하고 수치 오류는 각각 0이다. 두 영상이 아니라 600×1272 정지 프레임 두 개다. 반사/굴절과 감쇠 계산은 같고 AOV는 출력 색만 바꾼다.

- 정상 렌더: `frozen-runtime/.build-cache/live-volume/frozen-path-baseline/frame-000.png`
- 길이 표시: `frozen-runtime/.build-cache/live-volume/frozen-blue-length-aov/frame-000.png`
- 실제 진단: 각 폴더의 `paths-000.rgba16f`, `report.json`, `compiled-source.metal`, `state-000.json`

세 가로 단면의 픽셀을 확인했을 때 밝은 청록 영역의 파란 액체 통과 길이는 약 .05~.21 scene unit이고, 안쪽 본체는 약 .55~.72였다. 이 장면에서는 짧은 광학 경로와 색 전이의 대응이 확인된다. 폭과 형태가 실물과 맞는지, 어느 표면 재구성이 더 나은지는 별도 검증이 필요하다. 이 수치는 전체 화면의 통계나 재질 품질 점수가 아니다.

## 판정

앱 재질 소스 수정은 채택하지 않았다. 반짝임·색상 조절을 더하면 해결된다고 주장하지 않는다. 파란 본체에서 목·방울로 이어지는 실제 경계/두께와 맑은 액체 영역의 관계를 함께 보존하는 후속 후보가 필요하다. 이번에 앱에 넣는 변경은 빠른 흔들림 입력 전달이며, 실물 같은 두 액체 운동·재질의 완성은 아니다.
