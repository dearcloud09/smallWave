# smallwave · 빨간 배 수면 접촉 다듬기

현재의 작고 둥근 빨간 배를 유지하면서, 물 아래 선체가 회색 받침처럼 보이던 부분을 줄인 단일 기본안이다. 먼저 `index.html`의 402 × 874pt 전체 앱 화면에서 비교한다.

## 유지한 것

- 둥근 선체, 짧은 돛대, 상아색 천 돛, 작은 남색 구명환과 현재 빨강
- 원본 PNG, 모든 색상의 동일한 실루엣, 0.75 배율과 약 71pt 선체 폭
- 기준 앱의 UI, 글자, 배치, 물리·파동·자이로 입력과 부력·관성 상태
- 기존 볼륨 광학 및 480px 내부 렌더 해상도와 화면 합성

## 바꾼 것

1. 물을 통과해 보이는 선체의 합성 비중을 줄여, 불투명한 회색 타원이 물빛에 자연스럽게 이어지도록 했다. 이는 배 이미지의 표현 조정이며 물리나 액체 광학의 변경이 아니다.
2. 선체가 닿는 자리에만 얇은 접촉 그림자와 작은 물가장자리를 적용했다. 작은 물자국은 기존 선체 상대 속도에 따라 나타난다.
3. 배 텍스처에만 약한 mip bias(-0.35)를 적용해 작은 돛단·선체 줄무늬·구명환을 보존했다.
4. 폰을 눕힐 때는 기존 나무 선체의 불투명도를 유지한다. 기존 중력 값으로 수면 접촉 표현의 강도만 조절하며, 입력과 움직임은 바꾸지 않는다.

## 기준과 검증

- 기준 커밋: `7ecceaa45b8a241d23b33130063b3d9a61bfe5e3`.
- 실제 앱 변경: `SmallWave/Rendering/LiquidShaders.metal`, `SmallWave/Rendering/MobileVolumeOptics.metal`의 배 샘플링·접촉 합성 부분만.
- 검증 하네스 보완: `Tests/MiniatureArtReview.swift`의 정지 자세 캡처에도 시뮬레이션과 같은 `MotionSample`을 렌더러에 전달한다. 기준본과 후보에 동일한 하네스를 사용한다. 이 수정은 앱 실행에 포함되지 않는다.
- 5자세의 물리 상태 해시가 전후 동일하다. 기존 procedural boat 경로의 PNG는 바이트 단위로 동일하다.
- 180프레임 × 3색의 렌더가 시뮬레이션 상태를 변경하지 않음을 검사했다. 기존 입력→배 관성의 시간 관계를 유지한다.
- iPhone 17 Pro 시뮬레이터 앱 빌드·설치·실행 및 실제 SwiftUI 전체 화면 확인 완료. 물리 iPhone의 이번 아트 설치는 별도 통합 빌드 담당 작업에서 진행한다.
- 세부 해시와 픽셀 비교는 `polish-verification.json`, 자세별 상태는 `verification.json`, 움직임 상태는 `motion-trace.json`에 있다.

## 자료 읽기

- `primary-native.png`, `before-native.png`: 실제 iOS 시뮬레이터 앱 캡처. 1206 × 2622px를 402 × 874pt로 표시한다. 서로 다른 시점의 캡처다.
- `primary-*.png`, `before-*.png`: 같은 물리 상태에서 출력한 5자세의 네이티브 Metal 장면. 804 × 1748px. UI를 가짜로 덧씌우지 않았다.
- `primary-motion.mp4`: 현재 빨간 배의 6초 움직임. 합성 기울임 입력을 사용하며 실제 기기 센서 촬영은 아니다.
- `index.html`: 전체 화면을 먼저 보여주는 비교 자료. 화면 내부 컨트롤을 조작하는 앱 데모는 아니다.

## 남은 표현 한계

배는 기존 볼륨 안에 놓인 2D 텍스처 기반 미니어처다. 폰을 눕혀도 새로운 3D 측면이 생기지 않는다. 극단적인 침수에서는 기존 수면 굴절 경계가 선체를 가로지를 수 있다. 이번 수정은 이 구조 안에서 정면 가독성과 수면 접촉을 개선한다.

이 자료는 아트 변경을 동결된 기준본에서 검증한 기록이다. 같은 폴더에서 병행 중인 다른 작업의 액체·입력 수정은 이 아트 전후 비교에 포함되지 않는다.
